# Переговорный стол

Два человека заходят по ссылке, вводят имя, один создаёт комнату, второй подключается. Дальше видеосвязь, карточки ролей, таймеры, общая договорённость с подписями и разбор. Без регистрации и профилей.

## Что умеет

- Вход без регистрации: имя → создать комнату или открыть ссылку-приглашение (видно, кто зовёт и какой кейс).
- Лобби по шагам: собеседник → роли → правила → связь и старт. Роли выбирают оба в комнате, видно только имена персонажей; занятую роль можно попросить обменять или распределить случайно.
- Подсказки «Что сейчас делать» на каждом этапе (можно скрыть).
- Видеосвязь прямо на странице, индикатор уровня микрофона, подсветка того, кто говорит.
- Чек-лист перед стартом: собеседник на месте, камера и микрофон работают, связь есть.
- Подготовка: своя карточка (скрытую информацию можно спрятать с экрана), три вопроса к себе, «Готов» у обоих.
- Переговоры: общая договорённость с подписями, подсказки против размытых формулировок («постараюсь», «обсудим потом»), индикатор конкретности, личные заметки «что я узнал о собеседнике».
- Спорные детали вместо ведущего: оспорить придуманное обстоятельство, автор снимает его или спор фиксируется.
- Таймеры с напоминаниями (5 минут, минута, время вышло).
- Разбор: обе карточки, что стало со скрытой информацией, заметки и подготовка обоих, самооценка рядом, копирование итога.
- Реванш: тот же кейс со сменой ролей в той же комнате.
- Очки за партию и счёт между игроками в комнате (правила подсчёта — в «Правилах» на сайте и в `scoreRound` в server.js).
- Личная статистика: партии, % сделок, средние очки. Хранится в браузере (localStorage), без регистрации и cookies.

## Как устроено

- `server.js` — один Node-сервер: отдаёт страницу, держит комнаты в памяти, синхронизирует игроков по WebSocket и передаёт сигналы для видеосвязи.
- `public/index.html` — весь интерфейс.
- `cases.js` — кейсы. Новый кейс = скопировать объект, поменять `id` и тексты.

Чужая карточка физически не приходит в браузер до разбора: сервер отдаёт каждому только его роль.
Видео и звук идут напрямую между игроками (WebRTC), через сервер не проходят.

## Запустить у себя

Нужен Node.js 18+.

```
npm install
npm start
```

Открыть http://localhost:3000 в двух вкладках. На localhost камера работает без HTTPS.

## Выложить в интернет (бесплатно, ~10 минут)

**Render.com**

1. Залей папку в репозиторий на GitHub.
2. На render.com: New → Web Service → выбери репозиторий.
3. Настройки: Runtime `Node`, Build Command `npm install`, Start Command `npm start`, тариф Free.
4. Через пару минут получишь ссылку вида `https://peregovory.onrender.com`. HTTPS уже включён, камера будет работать.

Бесплатный Render засыпает после 15 минут без посетителей. Первое открытие после сна занимает ~50 секунд, потом всё быстро.
Если перезапустить сервер, текущие комнаты пропадут (они хранятся в памяти).

Подойдёт и Railway, Fly.io, любой VPS: главное, чтобы хостинг поддерживал WebSocket и HTTPS.

## Если видео не соединяется

Обычно видео соединяется напрямую. Но у части сетей (корпоративные, некоторые мобильные операторы) прямое соединение заблокировано, нужен TURN-сервер-посредник.

1. Зарегистрируйся на metered.ca (есть бесплатный лимит) или подними свой coturn.
2. В Render → Environment добавь переменные:
   - `TURN_URL` — адреса через запятую, например `turn:global.relay.metered.ca:80,turn:global.relay.metered.ca:443?transport=tcp`
   - `TURN_USER` — логин
   - `TURN_PASS` — пароль
3. Перезапусти сервис.

## Добавить кейс

Открой `cases.js`, скопируй объект кейса целиком, поменяй `id` (латиница, уникальный) и тексты. Поле `noDeal` — последствия, если игроки не договорились. `dur` — минуты на подготовку и разговор. После изменения перезапусти сервер (на Render это происходит само при пуше в GitHub).
